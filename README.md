# AutoPickup · 窗口识别自动化助手

> 一个 Windows 桌面小工具：**看懂游戏窗口里的中文界面 → 决定该怎么做 → 用虚拟手柄把动作做出来**，
> 并把整套业务循环写成一串可离线回放、可逐步验收的「原子流程」。
>
> 不注入进程、不读写游戏内存、不改游戏文件。全部通过「抓屏 + 系统自带 OCR + 虚拟手柄」完成。

---

## 这是什么

面向**重复性点击与切换**类玩法的通用自动化助手，做三件事：

1. **看**：抓取目标窗口画面，用系统自带 OCR 识别中文（暂停菜单、标签页、列表项、左下角提示……），可选模板匹配辅助。
2. **判断**：把「看到了什么」变成**证据**（处于哪个模式、菜单是否打开、出现了什么弹窗、有没有失败提示……），再由**判据**决定成功/失败。
3. **做**：把判断结果变成**动作**（按键、摇杆手势、开关防火墙），交给虚拟手柄执行——**动作只负责做，不自己判断成败**。

三层分开带来的最大好处：整套流程可以**离线回放**。把抓好的截图按脚本喂进去，不碰游戏就能验证这串流程对不对。

## 主要特性

| 能力 | 说明 |
| --- | --- |
| **纯外部覆盖层** | 分层透明窗口（点击穿透、不抢焦点、不注入），可在画面上实时画出识别区域与 OCR 词框，方便调参 |
| **中文 OCR 判定** | 系统 OCR + 多站点裁剪（整帧 / 标签条 / 列表焦点行 / 左下提示 / 中央弹窗），按“工作像素预算”统一缩放，跨分辨率稳定 |
| **抗 OCR 错字** | 关键词判据用字符命中计数（失败提示被读错字也能认出来）、焦点行用字符重合度匹配，不做整词相等 |
| **虚拟手柄动作** | 通过 ViGEm 虚拟手柄发按键与摇杆，窗口失焦也生效；无驱动时自动降级为键盘模拟并提示 |
| **音频时机** | 回环采集系统输出音量，在“安静 → 突然变响”的那一刻触发关键动作 |
| **联网开关** | 两条**互相独立**的防火墙规则：只拦某个服务的出站（游戏不掉线）／完全断网（故意掉线）。程序退出与流程失败时都确保**恢复联网** |
| **原子流程引擎** | 流程写成 JSON：观察 / 动作 / 判据三层分离，支持重试、超时、超时重试、失败策略（跳过·继续·中止·回卷），步骤结果可作为后续分支条件 |
| **离线回放验收** | 自带帧脚本回放：按脚本推进画面与时间轴，**不启动游戏**就能跑完整轮流程并输出每一步证据 |
| **单文件分发** | 内置资源首次运行释放到用户数据目录，发布产物是**一个 exe** |
| **数据可清理** | 日志自动轮转；自检页显示各项占用并支持一键清理临时文件 |

## 快速开始

### 方式一：下载单文件（推荐）

1. 到 Releases 页面下载 `AutoPickup.exe`；
2. 双击运行（首次运行会在用户数据目录释放内置资源）；
3. 在**自检页**点「使用向导」，按提示确认环境（窗口、抓帧、输入层、OCR）；
4. 在**参数页**确认「进程名 / 窗口类」与目标程序一致，并按需微调识别区域；
5. 在**流程页**设好轮数，点「开始班次」。

> 虚拟手柄需要 ViGEmBus 驱动。未安装时程序会提示，动作会退化为键盘模拟。

### 方式二：从源码构建

```powershell
# 依赖：.NET 8 SDK（Windows）
git clone https://github.com/LtcYGL/AutoPickup.git
cd AutoPickup
dotnet build                            # 开发构建
pwsh -File publish.ps1                  # 产出 dist\AutoPickup.exe（单文件）
pwsh -File publish.ps1 -SelfContained   # 自包含单文件（体积大，但无需装 .NET）
```

## 界面与热键

- **自检页**：环境状态灯、只读诊断、联网控制、数据占用与清理。
- **参数页**：全部可调参数（识别区域百分比、OCR 缩放、阈值、等待时间、热键……），改完即时生效。
- **流程页**：模式切换测试、封网开关、班次设置与启停、流程引擎开关。运行日志在下方，可折叠。

| 热键 | 作用 |
| --- | --- |
| **F6** | 显示/隐藏识别框（区域可视化 + OCR 词框） |
| **F7** | 封云存档 开/关（只拦存档服务，游戏不掉线） |
| **F8** | 完全断网 开/关（故意掉线） |

热键可在参数页修改，全局生效（目标程序在前台也能按）。

## 原子流程：把「操作」拆成三层

流程文件是普通 JSON（放在 `flows/`），一个步骤长这样：

```jsonc
{
  "id": "wait_story",
  "title": "等待到达故事",                          // 日志里显示的中文短标签
  "action": { "op": "waitmode", "target": "story", "ms": 300 },
  "expect": [ "fact:mode_reached eq true" ],        // 判据
  "onFail": "abort"                                 // 失败策略
}
```

- **观察**（纯读，不按键）：`mode` / `menuopen` / `dialog` / `toast` / `selectedtab` / `focusrow` / `text`
- **动作**（只做，不自验）：`tap` / `gesture` / `menu` / `tab` / `navigate` / `firewall` / `waitcue` / `waitmode` / `sleep`
- **判据**（决定成败）：`eq` / `ne` / `in` / `nin` / `gt` / `ge` / `lt` / `le` / `truthy` / `falsy` / `contains` / `like`

一条真实的业务循环就是这些原子的拼接：进线上 → 等到关键音频时刻立刻封锁 → 确认到达 → 验证出现失败提示 → 回故事 → 恢复联网。
**手势失败会自动改走暂停菜单流程**（与手动操作习惯一致）。

### 离线回放（不启动游戏也能验证）

```powershell
AutoPickup.exe --run-flow flows\shift_single.json --replay replays\shift\script.json
```

回放脚本给每帧标一个停留时长，并按动作定义“触发某动作就切到哪一帧”，于是**观察不推进、动作推进**，
整条流程能在几秒内跑完并输出每一步的证据轨迹。

仓库自带回归脚本，一条命令跑完所有流程：

```powershell
pwsh -File run_replay_regress.ps1
```

## 数据目录

首次运行会在 `%LOCALAPPDATA%\AutoPickup\` 下建立：

| 目录 / 文件 | 内容 | 会不会增长 |
| --- | --- | --- |
| `settings.json` / `ui.json` | 参数与界面布局 | 否 |
| `flows/` | 流程定义（可自行修改） | 否 |
| `native/` | 首次运行释放的原生库 | 否 |
| `logs/` | 运行日志（**超过 3MB 自动轮转**，只留 1 份历史） | 会 |
| `frames/` `samples/` `diag/` | 采帧、样本、诊断输出（都需手动触发才产生） | 会 |

**自检页 →「数据与占用」** 会显示各项占用，并提供「清理临时文件」一键清理（只删会增长的三类，不动参数、流程与模板）。

## 目录结构

```
AutoPickup.csproj        项目文件
Program.cs               入口 + 命令行诊断工具（--run-flow / --profile-read / --run-shift …）
AppRuntime.cs            组件组装
Config/                  参数模型、持久化、参数页数据源
Core/
  Capture/               窗口抓帧（PrintWindow 优先，屏幕拷贝兜底）
  Vision/                预处理、识别站点、标签条与焦点行读取、模板匹配
    Ocr/                 系统 OCR 封装（含中文语言包探测）
  Input/                 输入层：虚拟手柄 / 键盘 / 空实现
  Audio/                 回环音量与“安静→响亮”时机检测
  Net/                   防火墙规则（两条独立规则）
  Fsm/                   传统状态机流程（保留为回退路径）
  Flow/                  原子流程引擎：观察 / 动作 / 判据 / 宿主 / 回放
  Menus/                 菜单项注册表与文本模糊匹配
  Native/                Win32 与原生库封装
  Jobs/                  班次编排（原子引擎 或 传统流程）
Ui/                      WinForms 界面：主窗口、覆盖层、向导、参数页
flows/                   流程定义（JSON）
docs/                    架构说明
publish.ps1              一键打包单文件 exe
run_replay_regress.ps1   离线回放回归
```
